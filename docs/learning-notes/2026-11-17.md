## 새로 배운 내용

### 구글 애널리틱스(GA4)
- **측정 ID(`G-`)와 Tag Manager 컨테이너 ID(`GTM-`)는 다른 것.** 직접 코드를 넣을 때는 `G-` 측정 ID를 쓴다. 둘을 같이 설치하면 같은 방문이 두 번 잡힌다.
- 한 페이지짜리 앱(SPA)은 화면이 바뀌어도 새로고침이 없어서, 자동 `page_view`로는 이동이 잡히지 않는다. 이동마다 `page_view`를 직접 보내야 하고, 해시 주소(`#/...`)는 GA가 구분하지 못한다.
- 이벤트 매개변수(`post_id` 등)는 **맞춤 측정기준(범위: 이벤트)으로 등록해야** 보고서에서 나눠 볼 수 있다. 등록하지 않으면 이벤트 개수만 보인다.
- 지역, 기기, OS, 유입, 종료 페이지는 코드 없이 GA가 기본으로 모은다.
- 관리자 본인 방문 제외: `window['ga-disable-측정ID'] = true`와 브라우저 표시(localStorage).
- 향상된 측정의 "기록 이벤트에 따른 페이지 변경"을 켜 두면 직접 보내는 `page_view`와 겹친다.

### 링크 미리보기(OG)와 라우팅
- 카카오톡, 슬랙 같은 로봇은 **자바스크립트를 실행하지 않고** HTML 머리말의 `og:*` 태그만 읽는다. React에서 메타 태그를 바꾸는 방식은 로봇에게 보이지 않는다.
- 주소의 `#` 뒤는 서버에 전달되지 않는다. 그래서 해시 라우터로는 글별 OG가 불가능하다.
- GitHub Pages는 서버 코드를 못 돌린다. 그래서 **빌드 후에 글마다 정적 HTML을 생성**하고, 없는 경로는 `404.html`(앱 화면 복사본)이 받게 하는 방식으로 일반 주소를 지원한다. 폴더 주소를 슬래시 없이 열면 301로 슬래시를 붙여 이동한다.
- 예전 주소(해시)는 작은 스크립트로 새 주소로 바꿔 준다.
- 카카오톡은 미리보기를 캐시한다. 고친 뒤에도 옛 모습이 나오면 카카오 디버거에서 캐시를 지운다.
- Firestore는 REST API(`documents:runQuery`)로도 읽을 수 있다. 공개 규칙과 같은 조건(`status`, `visibility`)으로 질의해야 허용된다.

### GitHub Actions
- 정기 실행(`schedule`)은 저장소에 활동이 60일 없으면 자동으로 멈춘다. 푸시하면 다시 켜진다.
- `concurrency`의 `cancel-in-progress`와 그룹 설계에 따라 새 배포가 옛 배포를 끊거나, 반대로 옛 배포가 새 배포를 덮어쓸 수 있다.
- 오류를 "변경 없음"으로 삼키면(fail-open) 사이트가 조용히 옛 상태로 멈춘다. 읽기에 실패하면 실패로 끝내야 알림이 간다.

### CSS와 화면
- `color-mix(in srgb, 글자색 비율%, 배경색)`로 두 색만 정하면 회색 단계를 자동으로 만들 수 있다. 색 조합을 바꿔도 다른 단계가 따라온다.
- `100svh`는 모바일 주소창을 고려한 화면 높이. 글 하나를 한 화면에 맞추려면 카드 높이를 `100svh - 위아래 여백`으로 둔다.
- 스크롤 이동 체감: 처음 반응이 늦으면 오류처럼 느낀다. 시작은 빠르게, 끝에서 서서히 줄이는 곡선(easeOut)이 낫다. 느림을 시간 탓만 하지 말고 겹친 효과(smooth 스크롤, 나타나기 대기)를 먼저 의심한다.
- 접근성: `prefers-reduced-motion`을 지키고, 로딩 원은 0.25초 안에 끝나면 보이지 않게 한다.

### Firebase와 요금
- Firebase Storage는 2026년 2월부터 기본 버킷도 Blaze(종량제) 요금제가 있어야 쓸 수 있다. Blaze여도 무료 사용량이 있다(저장 5GB, 다운로드 100GB 등, 공식 기준을 사용 시점에 다시 확인).
- 같은 프로젝트의 기본 데이터베이스를 다른 저장소가 규칙으로 덮어쓸 수 있어서, 이 블로그는 이름 있는 데이터베이스(`blog`)를 따로 쓴다.
- 규칙(`firestore.rules`)에는 실제 관리자 이메일 대신 자리표시자를 두고, 콘솔에만 실제 값을 넣는다.

- 인수인계 문서(`AGENTS.md`)에 현재 상태, 디자인 규칙, 남은 일을 두면 다른 AI가 이어받기 쉽다.
- 사용자가 준 레퍼런스는 "원리를 따라 만들기"가 아니라 "거의 그대로 따라 만들기"로 받아들이고, 싫다고 한 것(예: 첫 레퍼런스)은 빼고 진행한다.
- 확인하지 못한 것(실제 휠 감각, 카카오 미리보기 등)은 완료로 적지 않고 확인 대기로 표시한다.
