# 블로그 2차 개선 PRD: 데이터 분석 강화

| 항목 | 내용 |
|---|---|
| 문서 상태 | 초안 (검토 요청) |
| 작성일 | 2026-11-18 |
| 대상 서비스 | 기획 노트 (React SPA, GitHub Pages, Firebase) |
| 분석 도구 | Google Analytics 4 (GA4) |
| 관련 문서 | GA 이벤트 택소노미(`docs/ga-report/ga-event-taxonomy.pdf`), 작업 기록(`docs/work-log.md`) |

## 1. 배경과 목적

1차 개선으로 디자인 개편, GA4 연결, 글별 링크 미리보기(OG)까지 갖췄다. 그러나 "어떤 글이 잘 읽히는가"를 판단하기에는 측정이 부족하다. 2차의 목적은 **블로그 콘텐츠 성과를 GA4 안에서 충분히 분석할 수 있게 하는 것**이며, 현재 GA에서 누락되었거나 확인할 수 없는 항목을 채운다.

## 2. 현황

### 2.1 측정 가능 여부

| 알고 싶은 것 | 현재 상태 | 판단 |
|---|---|---|
| 글별 방문자, 조회수 | `page_view` 직접 전송(`page_type`, `post_id`, `post_category`) | 가능 |
| 홈에서 글로 이동, 카테고리 관심 | `article_select`, `category_click` | 가능 |
| 평균 체류 시간 | GA 기본 "평균 참여 시간"만 존재 | 가능하나 글 길이 보정 불가 |
| 완독 | `article_scroll` 50%, 90% | 근사치만 가능 (짧은 글은 열자마자 도달, 빠른 스크롤도 완독으로 집계) |
| 좋아요, 스크랩, 댓글 | 기능 없음 | 불가 |
| 공유(링크 복사) | 복사 버튼은 있으나 이벤트 없음 | 측정 안 됨 |
| 사이트 내 검색 | 이벤트 없음 | 측정 안 됨 |
| 지역, 기기, 유입 경로, 이탈 | GA 기본 | 가능 |

### 2.2 누락, 확인 불가 항목

| 번호 | 문제 | 영향 |
|---|---|---|
| G1 | 이벤트 매개변수를 맞춤 측정기준으로 등록하지 않음 | 글별, 카테고리별 분해 불가. 등록 이전 데이터는 소급되지 않음 |
| G2 | 향상된 측정의 "기록 이벤트에 따른 페이지 변경" 상태 미확인 | `page_view` 이중 집계 가능성 |
| G3 | 글 길이, 발행일을 이벤트에 보내지 않음 | 체류 시간의 공정한 비교, 신규/기존 글 구분 불가 |
| G4 | 완독 판정이 스크롤 위치뿐 | 완독률 과대평가 |
| G5 | 링크 복사, 검색어 미측정 | 공유 의도와 독자 관심 주제 파악 불가 |
| G6 | 좋아요, 스크랩 기능 없음 | 반응 지표 부재 |
| G7 | 공유 경로별 유입 구분 불가 | 공유 링크를 통한 방문 식별 불가 |
| G8 | 관리자 제외가 로그인한 적 있는 브라우저에서만 동작 | 운영자 방문이 섞일 수 있음 |
| G9 | 실제 GA 화면(실시간, DebugView)에서 이벤트 검증을 하지 않음 | 구현 정확성 미보증 |

## 6. 요구사항 상세

### R1. GA 콘솔 설정 정비 `P0`
- 맞춤 측정기준(이벤트 범위)과 맞춤 측정항목 등록 (6.1 표 참고)
- 향상된 측정의 "기록 이벤트에 따른 페이지 변경" 해제
- 핵심 이벤트 지정: `article_read`, `share`, `like`, `scrap`
- 데이터 보관 기간 14개월로 설정
- 수용 기준: DebugView와 실시간 보고서에서 등록한 매개변수 값이 이벤트에 표시됨

### R2. 이벤트 공통 매개변수 보강 `P0`
모든 글 관련 이벤트에 읽는 시간(`read_minutes`)과 발행일(`post_published`)을 추가한다.
- 수용 기준: 글별 탐색 분석에서 글 길이와 발행일로 구분 가능

### R3. 완독 판정 개선 `P0`
- `article_read`: 글 방문당 1회, 아래 두 조건을 모두 만족할 때 전송한다.
  1. 본문 90% 지점을 지났다.
  2. 화면이 앞에 있던 활성 시간이 읽는 시간의 40% 이상이다. 단, 최소 10초.
- `article_time`: 활성 시간 15, 30, 60, 120초 도달 시 각각 1회 전송한다.
- 기존 `article_scroll`(50, 90)은 읽기 깊이 분석용으로 유지한다.
- 수용 기준: 열자마자 끝까지 내리는 테스트에서는 `article_read`가 발생하지 않고, 정상 속도로 읽는 테스트에서는 1회만 발생

### R4. 공유, 검색 이벤트 `P0`
- `share`: 링크 복사 버튼 클릭 시 전송
- `search`: 전체 글 검색창 입력이 멈춘 뒤(0.8초) 1회 전송. 빈 검색어와 1글자는 전송하지 않음
- 수용 기준: 두 동작이 DebugView에 1회씩 표시됨

### R5. 좋아요, 스크랩 기능 `P1`
- 글 상세 화면에 좋아요, 스크랩 버튼을 추가한다. 로그인 없이 사용하며, 방문자별 1회만 집계되고 다시 누르면 취소된다.
- 인증: Firebase 익명 인증
- 저장: Firestore `posts/{글ID}/reactions/{사용자ID}` 문서에 `like`, `scrap` 불리언 저장. 개수는 화면에서 집계한다.
- 보안 규칙: 쓰기는 본인 문서만, 읽기는 공개
- 수용 기준: 동일 사용자가 여러 번 눌러도 1회로 집계, 취소 시 감소, 규칙으로 타인의 반응 변경 불가

### R6. 링크 복사 UTM 부착 `P1`
- 링크 복사 시 `utm_source=share&utm_medium=copy_link`를 주소에 붙인다.
- 링크 미리보기(OG)와 canonical 주소에는 영향이 없어야 한다.
- 수용 기준: 해당 주소로 접속하면 GA 획득 보고서에 소스/매체가 `share / copy_link`로 표시됨

### R7. 글별 지표 확인용 GA 탐색 보고서 `P1`
GA4 "탐색"에서 글별(`post_id`)로 아래 지표를 볼 수 있는 보고서를 구성한다. 대시보드 개발은 후속 범위다.

| 지표 | 정의 |
|---|---|
| 조회수, 활성 사용자 | GA 기본 |
| 평균 참여 시간 | GA 기본 |
| 길이 보정 참여율 | 평균 참여 시간 ÷ (읽는 시간 × 60초) |
| 완독률 | `article_read` 이벤트 수 ÷ 글 조회수 |
| 다음 글 이동률 | `article_select`(`click_location=next_article`) ÷ 조회수 |
| 반응 수, 반응률 | (`share` + `like` + `scrap`) ÷ 조회수 |
| 재방문 사용자 비율 | GA 사용자 보고서 |

### R8. 인기 글 판단 기준 `P1`
조회수 하나로 판단하지 않고 아래 점수로 판단한다. 가중치는 초기값이며 데이터 수집 후 조정한다.

| 요소 | 가중치 | 의미 |
|---|---|---|
| 조회수 순위 | 30% | 많이 열렸는가 |
| 완독률 | 25% | 끝까지 읽었는가 |
| 길이 보정 참여율 | 20% | 시간을 들여 읽었는가 |
| 다음 글 이동률 | 15% | 더 읽고 싶어졌는가 |
| 반응률 | 10% | 공유, 좋아요, 스크랩을 이끌었는가 |

- 조회 30회 미만 글은 점수를 산출하지 않고 "표본 부족"으로 구분한다.
- 발행 후 동일 기간(예: 첫 30일)으로 맞춰 비교해 오래된 글이 유리해지는 것을 막는다.

### R9. 관리자 트래픽 제외 개선 `P2`
- 관리자로 로그인하면 이후 이벤트에 `traffic_type=internal`을 부착하고, GA 데이터 필터(내부 트래픽)로 제외한다.
- 필터를 "테스트" 상태로 확인한 뒤 "활성"으로 전환한다.
- 한계: 로그인한 적 없는 브라우저의 운영자 방문은 걸러지지 않는다.

### R10. 스크랩 목록 보기 `P2`
- 같은 브라우저에서 스크랩한 글을 모아 보는 목록 화면을 제공한다.

|---|---|---|
| 글별 지표 대시보드 | 블로그 관리자 화면 안에서 R7의 글별 지표와 R8의 인기 글 점수를 표로 제공한다. 데이터는 GA4 Data API를 서버 함수(Cloud Functions)로 호출해 가져오며, 관리자 로그인 계정만 조회할 수 있다. 외부 BI 도구는 사용하지 않는다. | R1~R4 완료 후 최소 2주 데이터 축적, GA 속성에 서비스 계정 조회 권한 부여, 서버 함수 사용 가능한 요금제 |
| 댓글 기능 | 글 상세 화면에 댓글 작성, 조회를 제공한다. 스팸 방지(작성 빈도 제한, 금칙어)와 관리자 삭제, 승인 기능을 포함하고 `comment` 이벤트를 추가한다. 반응 지표에 댓글 수를 합산한다. | R5(익명 인증, 반응 데이터 모델) 안정화, 운영 정책 수립 |
| 스크랩 모아보기 고도화 | 기기가 달라도 스크랩 목록을 유지하는 계정 연동 방식을 검토한다. | 로그인 방식 결정 |
| BigQuery 내보내기 | GA4 원본 이벤트를 내보내 사용자 단위, 경로 단위 분석을 수행한다. | 데이터 축적, 분석 요구 구체화 |

## 8. 단계별 일정(안)

| 단계 | 내용 | 포함 요구사항 | 규모 |
|---|---|---|---|
| M0 | 현재 이벤트의 GA 실시간, DebugView 검증과 콘솔 설정 | R1 | 반나절 |
| M1 | 측정 코드 개발: 공통 매개변수, 완독 판정, 공유와 검색, UTM | R2, R3, R4, R6 | 1일 |
| M2 | 좋아요, 스크랩 개발과 Firestore 규칙 | R5 | 2~3일 |
| M3 | GA 탐색 보고서 구성, 판단 기준 확정, P2 항목 | R7, R8, R9, R10 | 1일 |

M1 배포 후 약 1주일 데이터를 쌓은 뒤 R8의 가중치를 조정한다.

## 9. 비기능 요구

| 구분 | 내용 |
|---|---|
| 성능 | 측정 코드가 화면 표시를 막지 않는다. 스크롤 이벤트는 가볍게 처리한다 |
| 보안 | 반응 기능의 Firestore 규칙은 본인 문서만 쓰기를 허용한다. 관리자 계정 정보는 저장소에 두지 않는다 |
| 개인정보 보호 | 이름, 이메일 등 개인 식별 정보와 익명 인증 ID를 GA 이벤트에 전송하지 않는다 |
| 비용 | 현재 방문 규모에서 무료 사용량 범위 내로 추정하며, 방문량 증가 시 재검토한다 |

## 10. 위험과 대응

| 위험 | 영향 | 대응 |
|---|---|---|
| 방문량이 적어 통계적 의미가 낮음 | 순위 신뢰도 저하 | 최소 표본(조회 30회) 기준, 누적 후 판단 |
| GA 반영 지연(24~48시간), 임계값 | 지표 확인 지연 | 실시간, DebugView로 구현을 먼저 검증 |

| 익명 인증 남용 | 반응 수 왜곡 | 보안 규칙으로 문서 형태와 본인 문서만 허용 |
| 광고 차단 도구 | 일부 이벤트 누락 | 한계로 문서화, 추세 위주로 해석 |
