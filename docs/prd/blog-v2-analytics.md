# 기획 노트 블로그 2차 개선 PRD: 데이터 분석 강화

상태: 초안 (승인 대기) · 작성일: 2026-11-18 · 관련 문서: `docs/work-log.md`, `docs/ga-report/ga-event-taxonomy.pdf`

## 1. 배경과 목적

1차 개선으로 디자인, GA4 연결, 글별 링크 미리보기(OG)까지 갖췄다. 그러나 "어떤 글이 인기 있는가"를 판단하기에는 측정이 부족하다. 2차의 목적은 **블로그로서 콘텐츠 성과를 충분히 분석할 수 있게 하는 것**이며, 특히 지금 GA에서 누락되었거나 확인할 수 없었던 항목을 채운다.

## 2. 현황

### 2.1 측정 가능 여부

| 알고 싶은 것 | 현재 | 판단 |
|---|---|---|
| 홈, 전체 글, 글별 방문자와 조회수 | `page_view` 직접 전송(`page_type`, 글은 `post_id`, `post_category`, 제목) | 가능 (단, 실제 GA 화면 검증 전) |
| 평균 체류 시간 | GA 기본 "평균 참여 시간"만 있음 | 가능하지만 글 길이 보정 불가 |
| 완독 | `article_scroll` 50%, 90% | 근사치만. 짧은 글은 열자마자 동시 발생, 빨리 내려가도 완독으로 잡힘 |
| 홈에서 글로 이동, 카테고리 관심 | `article_select`, `category_click` | 가능 |
| 지역, 기기, OS, 유입, 이탈 | GA 기본 | 가능 |
| 좋아요, 댓글, 스크랩 | 기능 없음 | **불가** |
| 공유(링크 복사) | 복사 버튼은 있으나 이벤트 없음 | **측정 안 됨** |
| 사이트 내 검색 | 이벤트 없음 | **측정 안 됨** |

### 2.2 누락, 확인 불가 항목 (이번 개선 대상)

| 번호 | 문제 | 영향 |
|---|---|---|
| G1 | 이벤트 매개변수를 맞춤 측정기준으로 등록하지 않음 | 글별, 카테고리별 분해 불가, 소급 불가 |
| G2 | 향상된 측정의 "기록 이벤트에 따른 페이지 변경" 상태 미확인 | `page_view` 이중 집계 가능성 |
| G3 | 글 길이, 발행일 정보를 이벤트에 보내지 않음 | 체류 시간 비교 불공정, 신규와 오래된 글 구분 불가 |
| G4 | 완독 판정이 스크롤 위치뿐 | 완독률 과대평가 |
| G5 | 링크 복사, 검색어 미측정 | 공유 의도와 독자 관심 주제 파악 불가 |
| G6 | 좋아요, 스크랩, 댓글 기능 없음 | 반응 지표 부재 |
| G7 | 공유 경로별 유입 구분 불가 | 어디서 공유되어 온 방문인지 모름 |
| G8 | 관리자 제외가 로그인했던 브라우저에서만 동작, 확인 수단 없음 | 본인 방문이 섞일 수 있음 |
| G9 | 실제 GA 화면에서의 이벤트 검증 안 함 | 구현 정확성 미보증 |
| G10 | 글별 지표를 한눈에 보는 곳이 없음 | 인기 글 판단이 수작업 |
| G11 | 개인정보 안내 없음 | 방문자 증가 시 부담 |

## 3. 목표와 성공 기준

| 목표 | 성공 기준 |
|---|---|
| 글별 성과를 신뢰할 수 있게 측정 | 테스트 방문 시나리오 10종에서 코드 기준 이벤트 수와 GA 기록이 일치 |
| 완독과 체류를 글 길이에 상관없이 비교 | 글별 "완독률"과 "길이 보정 참여율"을 한 표로 산출 |
| 반응 지표 확보 | 공유, 좋아요, 스크랩이 글별 숫자로 확인됨 |
| 인기 글을 기준으로 판단 | 정의된 점수로 글 순위가 자동 산출되고, 최소 표본(조회 30회) 미만은 "표본 부족"으로 표시 |

## 4. 범위

포함: GA 설정 정비, 이벤트 보강, 완독 판정 개선, 공유와 검색 측정, 좋아요와 스크랩, 유입 구분, 글별 지표 대시보드, 개인정보 안내.
제외(이번에는 하지 않음): 댓글(스팸과 관리 부담), 이메일 구독, 유료 도구 연동, BigQuery 내보내기(데이터가 쌓인 뒤 재검토).

## 5. 요구사항

우선순위: P0 반드시, P1 이번 개선 안에, P2 여유가 있을 때.

### R1. GA 설정 정비 (P0, 코드 없음)
- 맞춤 측정기준(이벤트 범위) 등록: `post_id`, `post_title`, `post_category`, `post_published`, `category`, `click_location`, `page_type`, `scroll_depth`, `share_method`, `search_term`
- 맞춤 측정항목 등록: `read_minutes`, `engaged_seconds`
- 향상된 측정의 "기록 이벤트에 따른 페이지 변경" 끄기
- 핵심 이벤트 지정: `article_read`, `share`, `like`, `scrap`
- 데이터 보관 기간 14개월
- 수용 기준: DebugView와 실시간 보고서에서 위 값들이 이벤트에 붙어 보임

### R2. 이벤트 공통 매개변수 보강 (P0)
모든 글 관련 이벤트(`page_view`(글), `article_select`, `article_scroll`, 신규 이벤트)에 `read_minutes`(읽는 시간, 분), `post_published`(발행일, YYYY-MM-DD)를 추가한다.
- 수용 기준: 글별 탐색 분석에서 길이와 발행일로 나눌 수 있음

### R3. 완독 판정 개선 (P0)
- 새 이벤트 `article_read`: 글 방문당 한 번, 아래 두 조건을 모두 만족할 때 전송한다.
  1. 본문 90% 지점을 지났다.
  2. 화면이 앞에 있던 활성 시간이 글 읽는 시간의 40% 이상이다. (예: 5분 글은 2분 이상) 짧은 글은 최소 10초.
- 기존 `article_scroll`(50, 90)은 읽기 깊이 분석용으로 유지한다.
- 신규 `article_time`: 활성 시간 15초, 30초, 60초, 120초 도달 시 각 한 번(`engaged_seconds`).
- 수용 기준: 열자마자 끝까지 내리는 테스트에서는 `article_read`가 오지 않고, 천천히 읽는 테스트에서는 한 번만 옴

### R4. 공유와 검색 측정 (P0)
- `share`: 링크 복사 버튼 클릭 시. `share_method=copy_link`, `post_id` 등 공통 매개변수
- `search`: 전체 글 검색창에서 입력이 멈춘 뒤(0.8초) 한 번, `search_term`, 결과 수. 빈 검색어와 1글자는 보내지 않는다.
- 수용 기준: 두 동작이 DebugView에 한 번씩 보임

### R5. 반응 기능: 좋아요, 스크랩 (P1)
- 글 상세에 좋아요와 스크랩 버튼. 로그인 없이 쓸 수 있고(Firebase 익명 인증으로 방문자별 한 번만 가능), 다시 누르면 취소.
- 저장: Firestore `posts/{글ID}/reactions/{사용자ID}` (`like`, `scrap` 불리언). 글에는 집계 숫자를 두지 않고 화면에서 개수를 센다(규모가 작음).
- 규칙: 본인 문서만 쓰기, 읽기는 공개. 관리자는 집계를 읽을 수 있음.
- 스크랩 보기: 스크랩한 글만 모아 보는 화면은 이번 범위에 넣지 않고, 같은 브라우저에서 목록 확인만(P2).
- GA 이벤트: `like`, `unlike`, `scrap`, `unscrap` (공통 매개변수 포함)
- 수용 기준: 한 사용자가 여러 번 눌러도 1회로 집계되고, 취소하면 줄어듦. 규칙으로 다른 사람의 반응을 바꿀 수 없음

### R6. 유입 구분 (P1)
- 링크 복사 시 주소에 `utm_source=share&utm_medium=copy_link`를 붙여 복사한다. (미리보기와 canonical 주소에는 영향이 없도록 확인)
- 수용 기준: 그 주소로 접속하면 GA 획득 보고서에 소스/매체가 `share / copy_link`로 보임

### R7. 관리자 제외 개선 (P2)
- 관리자로 로그인하면 이후 이벤트에 `traffic_type=internal`을 붙이고, GA 데이터 필터(내부 트래픽)로 제외한다. 필터를 "테스트" 상태로 먼저 켜서 확인한 뒤 "활성"으로 바꾼다.
- 한계: 로그인한 적 없는 브라우저의 본인 방문은 걸러지지 않는다. 문서에 한계를 명시한다.

### R8. 글별 지표 대시보드 (P1)
방식은 열린 질문 Q2에서 결정. 어느 쪽이든 글별로 아래 표를 만든다.

| 지표 | 정의 |
|---|---|
| 조회수, 활성 사용자 | GA 기본 |
| 평균 참여 시간 | GA 기본 |
| 길이 보정 참여율 | 평균 참여 시간 ÷ (읽는 시간 × 60초) |
| 완독률 | `article_read` ÷ 글 조회수 |
| 다음 글 이동률 | `article_select`(`click_location=next_article`) ÷ 조회수 |
| 반응 수 | `share` + `like` + `scrap` |
| 반응률 | 반응 수 ÷ 조회수 |
| 재방문 사용자 비율 | GA 사용자 보고서 |

### R9. 인기 글 판단 기준 (P1)
조회수 하나로 정하지 않고 점수로 판단한다. 가중치는 초안이며 데이터를 본 뒤 조정한다.

| 요소 | 가중치 | 비고 |
|---|---|---|
| 조회수 순위 | 30% | 많이 열렸는가 |
| 완독률 | 25% | 끝까지 읽었는가 |
| 길이 보정 참여율 | 20% | 시간을 들여 읽었는가 |
| 다음 글 이동률 | 15% | 더 읽고 싶어졌는가 |
| 반응률 | 10% | 공유, 좋아요, 스크랩을 이끌었는가 |

- 조회 30회 미만 글은 점수 대신 "표본 부족"으로 표시한다.
- 같은 글을 발행 후 기간(예: 첫 30일)으로 맞춰 비교한다. 오래된 글이 유리해지는 것을 막기 위해서다.

### R10. 개인정보 안내 (P2)
하단에 개인정보 처리와 쿠키 안내 문구를 넣고, 필요하면 동의 후에만 측정하도록(GA 동의 모드) 바꾼다. 방문자 규모와 대상 지역에 따라 결정한다(Q5).

## 6. 비기능 요구
- 성능: 측정 코드가 화면 표시를 막지 않는다. 스크롤 이벤트는 가볍게 처리한다.
- 보안: 반응 기능의 Firestore 규칙은 본인 문서만 쓰기 허용. 관리자 이메일은 저장소에 넣지 않는다.
- 개인정보: 이름, 이메일 등을 GA 이벤트에 보내지 않는다. 익명 인증 ID도 GA에 보내지 않는다.
- 비용: 이번 범위는 Blaze 요금제의 무료 사용량 안에서 가능하다고 본다(방문량 확인 후 재검토).

## 7. 단계와 일정(안)

| 단계 | 내용 | 규모 |
|---|---|---|
| M0 | 현재 이벤트의 실제 GA 검증(실시간, DebugView), R1 콘솔 설정 | 반나절, 사용자 작업 포함 |
| M1 | R2, R3, R4, R6: 공통 매개변수, 완독 판정, 공유와 검색, 유입 구분 | 1일 |
| M2 | R8, R9: 대시보드와 인기 글 점수 | 1~2일(방식에 따라) |
| M3 | R5: 좋아요와 스크랩 | 2~3일 |

M0 이후 약 일주일 데이터를 쌓은 뒤 M2 점수 가중치를 조정한다.

### Q2 후속: 관리자 대시보드의 데이터 출처 (결정 필요)
- 안 A: GA4 Data API를 Cloud Functions로 호출해 관리자 화면에 표시. GA 숫자와 일치하지만 서버 함수 구성이 필요하다(Blaze 사용 중).
- 안 B: 이벤트를 Firestore에도 직접 기록하고 화면에서 집계. 서버 없이 가능하고 완독률 등 자체 계산이 쉽지만 GA 숫자와 약간 다를 수 있다(광고 차단 등).

## 10. 후속 목표 (이번 범위 밖)
- 3차: 댓글 기능(스팸 방지, 관리자 승인 또는 삭제 포함)
