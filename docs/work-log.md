# 작업 기록과 문제 해결

진행하면서 생긴 문제와 해결 과정을 시간 순서로 적는다. 새 문제가 생기면 맨 아래에 같은 형식으로 추가한다.

형식: 증상 → 원인 → 해결 → 다음에 확인할 것

## 진행 현황

| 단계 | 내용 | 상태 |
| --- | --- | --- |
| 1차 | 첫 화면 GitHub Pages 배포 (`jicongjy.github.io/blog/`) | 완료 |
| 2차 | 전체 5개 화면 시안 (Claude 아티팩트) | 완료 |
| 3차 | 관리자 로그인, 글쓰기, 목록 반영 | Firebase 설정 대기 |
| 4차 | 수정, 삭제, 공개/비공개 | 화면은 구현됨, Firebase 연결 후 확인 |

## 결정 사항

- 배포는 GitHub Pages, 데이터와 로그인은 Firebase(Authentication, Firestore). Firebase Hosting은 쓰지 않는다.
- 디자인은 티스토리 스킨 "Jicong Notes v0.2" 기준. 폰트는 Pretendard만, 배경은 흰색, 문구는 담백하게.
- 모든 글에 썸네일. 이미지가 없으면 카테고리와 번호로 만든 표지를 쓴다.
- 기존 Firebase 프로젝트 `gen-lang-client-0559087225` 안에 `blog` 데이터베이스를 따로 만든다. 다른 저장소가 기본 데이터베이스에 자기 규칙을 배포하기 때문에, 같은 데이터베이스를 쓰면 규칙이 덮어써질 수 있다.
- 관리자는 구글 계정 한 개로 제한한다. 화면은 `VITE_ADMIN_EMAIL`로, 실제 차단은 `firestore.rules`로 한다.
- 설정값은 코드에 넣지 않고 `.env`(로컬)와 GitHub 저장소 Variables(배포)로 넣는다.

## 문제와 해결

### 1. macOS에서 `sed -i`가 실패함
- 증상: `unterminated substitute pattern` 오류.
- 원인: macOS의 sed는 `-i` 뒤에 백업 확장자 인자가 필요해서 GNU sed와 다르게 동작한다.
- 해결: 파일 수정은 python이나 편집 도구로 한다.

### 2. 디자인이 예전 포트폴리오(검정+라임)를 따라감
- 증상: 현재 포트폴리오와 다른 분위기로 나옴.
- 원인: 예전 v2 디자인을 기준으로 삼았다.
- 해결: 실제 배포된 `/portfolio/`를 열어 현재 디자인을 확인하고 다시 만들었다.
- 다음에 확인할 것: 기준 디자인은 "지금 배포된 화면"을 직접 열어서 확인한다.

### 3. 첫 시안이 "촌스럽다"는 피드백
- 증상: 에디토리얼 책 펼침면, 베이지 종이 톤, 세리프 폰트가 맞지 않음.
- 원인: 참고 이미지의 인쇄물 느낌을 그대로 옮겼다.
- 해결: 티스토리 스킨(회색 바탕, 흰 패널, 좌측 카테고리, 3열 타일)을 가져와 발전시켰다. 흰색과 Pretendard만 사용.

### 4. 글 목록 화면이 빈 화면이 됨 (`destroy is not a function`)
- 증상: 페이지가 하얗게 나오고 콘솔에 `destroy is not a function`.
- 원인: `useEffect(() => window.scrollTo(0, 0), [pathname])`처럼 화살표 함수가 값을 반환했다. useEffect는 정리 함수만 반환할 수 있다.
- 해결: 중괄호로 감싸 아무것도 반환하지 않게 했다. `useEffect(() => { window.scrollTo(0, 0) }, [pathname])`
- 다음에 확인할 것: 브라우저 콘솔에 예전 오류가 남아 있을 수 있어서, 새로고침 후 새로 뜬 오류만 본다.

### 5. 큰 제목이 칸을 넘침
- 증상: 표지 제목 "PLANNING"이 칸 밖으로 나감.
- 원인: Pretendard 800 굵기에서 글자 폭이 커졌다.
- 해결: 글자 크기를 `clamp(40px, 5.6vw, 92px)`로 줄였다.

### 6. 아티팩트 글쓰기 화면이 게시되지 않음
- 증상: 첫 게시에서 변경이 반영되지 않음.
- 해결: 같은 파일로 다시 게시해 반영했다.

### 7. Firebase 연결 방식 정리
- 증상: 콘솔에서 Hosting의 `site`, `firebase deploy --only hosting:...` 안내가 나옴.
- 원인: 웹 앱 등록 마지막 단계에 Hosting 안내가 함께 나오는 것이다.
- 해결: 이 블로그는 GitHub Pages로 배포하므로 Hosting은 건너뛴다. 설정값(`firebaseConfig`)만 `VITE_FIREBASE_*`에 옮긴다. 가져오는 방식은 npm(`firebase` 패키지)을 쓴다. script 태그 방식은 쓰지 않는다.
- 다음에 확인할 것: Firebase 설정값이 비어 있으면 사이트는 미리보기 모드(브라우저 저장소)로 동작하고, 화면이 깨지지는 않는다.

### 8. 기존 프로젝트의 규칙 충돌 위험
- 증상: 같은 Firebase 프로젝트를 쓰는 다른 저장소(after8-chat, jicong-dashboard, bookservice)가 기본 데이터베이스에 규칙을 배포한다.
- 원인: Firestore 규칙은 데이터베이스마다 하나다. 같은 기본 데이터베이스에 블로그 규칙을 넣으면 서로 덮어쓴다.
- 해결: `blog`라는 이름의 별도 데이터베이스를 만들고 `VITE_FIREBASE_DATABASE_ID=blog`로 연결한다.
- 다음에 확인할 것: 데이터베이스를 만들 때 "프로덕션 모드"를 고른다. 테스트 모드는 일정 기간 누구나 읽고 쓸 수 있다.

### 9. 본문 입력 방식 변경 (마크다운 → 텍스트 에디터)
- 요청: 마크다운 문법 대신 글자 서식을 눌러서 쓰는 에디터, 카테고리는 선택형.
- 적용: Tiptap 에디터(제목, 소제목, 굵게, 기울임, 목록, 번호, 인용, 링크, 되돌리기). 카테고리는 드롭다운이고 목록은 `src/data/categories.js`에서 관리한다.
- 저장 형식: 본문을 HTML로 저장한다. 화면에 그릴 때는 DOMPurify로 허용한 태그만 남긴다(글쓰기 권한이 있는 계정만 저장할 수 있지만 이중으로 막는다).
- 예전 글 호환: 마크다운으로 저장된 글(샘플 포함)은 열 때 HTML로 바꿔서 보여 주고, 수정 후 저장하면 HTML로 바뀐다.
- 확인: 로컬 미리보기 모드에서 서식 적용, 발행, 예전 글 수정 열기를 확인했다. 콘솔 오류 없음.
- 다음에 확인할 것: 실제 Firebase에서 저장과 조회. 이미지 삽입은 아직 없고 썸네일은 주소 입력 방식이다.

### 10. 배포 실패: `npm ci` 잠금 파일 불일치
- 증상: 에디터 패키지를 추가한 뒤 GitHub Actions 빌드가 `npm ci` 단계에서 실패. `Missing: @emnapi/core ... from lock file`.
- 원인: `package-lock.json`이 `package.json`과 맞지 않았다. 로컬에서 패키지를 추가하면서 일부 하위 패키지(선택 의존성)가 잠금 파일에 빠졌다.
- 해결: `node_modules`와 잠금 파일을 지우고 `npm install`로 다시 만든 뒤, 로컬에서 `npm ci`가 통과하는지 확인하고 다시 올렸다.
- 다음에 확인할 것: 패키지를 추가하면 푸시 전에 `npm ci`가 통과하는지 확인한다.

### 11. 카테고리를 DB로 관리
- 요청: 카테고리를 선택형으로 하려면 관리 메뉴와 DB가 필요하다.
- 적용: Firestore `categories` 컬렉션(name, order). 관리 화면 `/admin/categories`에서 추가, 이름 변경, 순서 이동, 삭제. 글쓰기 선택지, 사이드바, 전체 글의 카테고리 칩이 모두 이 목록을 쓴다.
- 규칙: 이름을 바꾸면 그 카테고리의 글도 함께 바꾼다. 글이 있는 카테고리는 삭제할 수 없다. 같은 이름은 추가할 수 없다.
- 처음 관리자가 열었을 때 비어 있으면 기본 카테고리(기획, 설계, 운영)를 만든다.
- 필요한 조치: `firestore.rules`에 `categories` 규칙이 추가되어, `blog` 데이터베이스 규칙을 다시 게시해야 한다. 게시 전에는 카테고리 읽기가 막혀 사이드바 카테고리가 비어 보인다.
- 함께 고친 것: 에디터 미리보기에서 `category is not defined` 오류(치환 실수).

### 12. "Firebase 연결 전" 안내가 보임
- 확인: 배포된 사이트의 빌드 결과에는 프로젝트 ID, 데이터베이스 `blog`, 관리자 설정이 들어 있어 연결된 상태다.
- 원인 추정: 오래된 화면이 브라우저에 남았거나, 로컬 개발 서버가 `.env`를 읽기 전에 켜진 것. 확인한 사실은 배포본이 연결되어 있다는 것까지다.
- 해결: 강력 새로고침(Cmd+Shift+R). 로컬이면 개발 서버를 껐다 켠다.

### 13. 화면 수정 (포트폴리오 링크, 목차, 마스코트)
- 포트폴리오로 가는 링크를 사이드바와 상단 메뉴에서 삭제했다.
- 사이드바 카테고리 간격을 2px에서 14px로 넓히고, 글 수 숫자를 빨간색(#c2413b)으로 바꿨다.
- 사이드바 하단 버튼 문구를 "글 작성하기"로 통일했다. 로그인하지 않은 상태에서 누르면 글쓰기 화면의 로그인 안내로 이동한다.
- 마스코트의 눈동자가 마우스 포인터를 따라간다. 움직임 줄이기 설정을 켠 기기에서는 움직이지 않는다.
- 글 상세를 2열로 바꿨다. 왼쪽은 고정 목차(소제목 기준, 읽는 위치 강조, 클릭하면 이동), 오른쪽은 제목, 요약, 썸네일, 본문. 썸네일은 본문과 같은 너비(720px)이고 비율은 16:9다. 화면이 좁으면 목차가 위로 올라간다.
- 목차는 본문의 제목과 소제목에서 만든다. 제목을 하나도 넣지 않은 글은 "이 글에는 목차가 없습니다"로 표시된다.
- 이름 충돌 방지: 클릭 이동에 `#` 링크를 쓰면 해시 라우터와 부딪혀서 버튼과 `scrollIntoView`를 썼다.

### 14. 홈을 잡지형으로 교체
- 구성: 첫 화면(큰 소개 문장, 카테고리 목록과 이미지) 아래에 글 섹션(왼쪽 번호 목록, 오른쪽 큰 이미지와 글 정보). 레퍼런스에 맞춰 선을 쓰지 않고 여백으로 구분한다.
- 소개 문장은 회색 바탕에 "문제 정의", "화면 설계", "운영"만 검정이다. 문장은 코드(`src/pages/Home.jsx`)에 고정되어 있다.
- 카테고리 이름에 마우스를 올리면 강조와 이미지가 바뀌고, 누르면 아래 글 섹션으로 이동해 그 카테고리 글만 보여 준다. "전체 보기"로 되돌린다.
- 글에 이미지가 없으면 카테고리 이미지를 쓴다. 이미지는 이름(기획, Planning 등)이나 순서로 찾아서 이름을 바꿔도 이어진다. 이미지 파일은 `public/images/`(JPEG, 270~430KB).
- 홈에서 마스코트, 사이드바, 색 강조를 뺐다. 전체 글, 글 상세, 글쓰기 화면은 아직 이전 디자인이다. 다음 단계로 통일한다.
- 새로 만들어지는 기본 카테고리를 Planning, Design, Operations로 바꿨다. 이미 DB에 있는 카테고리는 관리 화면에서 이름을 바꿔야 한다(글도 함께 바뀐다).
- 확인: 로컬에서 hover 전환, 카테고리 선택 후 이동과 필터, 선 없음(테두리 0개), 모바일 폭(390px) 가로 넘침 없음을 확인했다.

### 15. 글 상세를 홈과 같은 분위기로 통일
- 상단 한 줄(사이트 이름, 메뉴, 시계)을 홈과 같은 `HmTop`으로 공유했다. 상자, 선, 테두리는 쓰지 않는다(테두리 있는 요소 0개 확인).
- 2열: 왼쪽 고정 목차(Contents, 소제목 기준, 현재 위치는 검정), 오른쪽에 메타, 큰 제목, 요약, 이미지, 본문. 이미지와 본문의 너비는 같다(720px).
- 이미지가 없는 글은 카테고리 이미지를 쓴다. 맨 아래에 다음 글 3개(이미지, 날짜, 제목)와 글 번호가 붙은 저작권 줄을 둔다.
- 본문은 16px, 소제목은 굵게, 인용은 회색 들여쓰기(배경 상자 없음), 링크는 밑줄이다.
- 겪은 문제: 새 스타일의 여백이 `.hm p { margin: 0 }`에 가려져 요약과 관리 링크 사이가 붙어 보였다. 선택자를 `.hm .pd-...`로 올려 해결했다.
- 겪은 문제: 이미 열려 있는 브라우저 탭은 해시만 바뀌어서 이전 화면이 남는다. 새로고침 후 확인했다.
- 남은 화면: 전체 글 목록, 글쓰기, 로그인, 카테고리 관리는 이전 디자인이다.

### 16. 전체 글, 스크롤 단위, 파비콘, 임시 글
- 전체 글(`/notes`)을 홈과 같은 분위기로 바꿨다: 왼쪽 카테고리 필터와 검색, 가운데 번호 붙은 글 색인(번호, 제목, 카테고리, 날짜), 오른쪽에 마우스를 올린 글의 이미지. 예전 사이드바 화면과 `WithSidebar`, `Sidebar`는 삭제했다.
- 삭제하려던 `Mascot.jsx`는 로그인 화면이 아직 쓰고 있어서 빌드가 실패했다(`Could not resolve Mascot.jsx`). 파일을 되살려 해결했다. 로그인 화면을 새 디자인으로 바꿀 때 함께 정리한다.
- 홈 스크롤 단위: CSS 스크롤 스냅(`y mandatory`)으로 첫 화면, 글 하나씩, 맨 아래 순서로 멈춘다. 글 간격은 약 683px, 화면 높이 800px에서 스냅 위치를 계산으로 확인했다. 움직임 줄이기 설정에서는 끈다.
- 확인하지 못한 것: 테스트 브라우저의 가상 휠, 키 입력은 스크롤이 발생하지 않아서(항상 맨 위로 되돌아감) 실제 마우스 휠과 트랙패드의 한 번에 한 칸 이동은 직접 확인이 필요하다. 스냅 위치로 보내는 프로그램 스크롤은 정상 동작했다.
- 파비콘을 작은 검정 원(반지름 8, 32px 기준)으로 바꿨다.
- 임시 글 4개: 관리자 화면(`/admin/categories`)의 "임시 글 4개 등록" 버튼으로 등록한다. Firestore는 관리자 로그인이 있어야 쓸 수 있어서 제가 직접 넣을 수 없다. 아이디가 고정이라 여러 번 눌러도 중복되지 않는다(로컬에서 두 번 눌러 7개가 11개가 되는 것으로 확인).

### 17. Google Analytics(GA4) 연결
- 목표: 홈 방문자 수, 페이지별 방문자 수, 지역, 기기, OS 통계, 가장 많이 읽힌 글.
- 코드(`src/lib/analytics.js`): 측정 ID(`VITE_GA_MEASUREMENT_ID`)가 있고 배포본일 때만 켜진다. 로컬 개발과 미리보기는 집계하지 않는다.
- 해시 주소 문제: 이 블로그는 `#/post/...` 주소를 쓰는데 GA는 주소의 `#` 뒤를 구분하지 못한다. 그대로 두면 모든 페이지가 하나로 합쳐진다. 그래서 자동 page_view를 끄고(`send_page_view: false`), 화면 이동마다 `/blog/post/아이디` 같은 가상 경로로 page_view를 직접 보낸다.
- 보내는 것: 홈(`/`, 제목 홈), 전체 글(`/notes`), 글 상세(경로와 함께 페이지 제목을 글 제목으로, post_id와 post_category 매개변수), 본문 80% 지점을 지나면 `read_complete`(글당 1회), 홈에서 카테고리를 누르면 `select_category`.
- 집계하지 않는 것: 비공개 글과 임시저장 글, 글쓰기와 관리자 화면, 관리자로 로그인한 브라우저(이 브라우저에 `blog:no-track` 표시를 남겨 이후 방문도 제외).
- 확인: 가짜 측정 ID로 빌드해서 `dataLayer`에 config, 홈 page_view, 글 page_view(글 제목, 아이디, 카테고리), read_complete가 쌓이는 것을 확인했다. 실제 GA 화면에서의 집계는 측정 ID를 넣은 뒤 확인해야 한다.
- 겪은 점: 로컬에서 만든 테스트 빌드가 실제 Firebase 글('제목')을 불러와서 그 글로 테스트가 됐다. 테스트 서버와 임시 폴더는 삭제했다.
- 남은 작업(콘솔): 측정 ID 발급, GitHub 변수 등록, 향상된 측정의 "기록 이벤트에 따른 페이지 변경" 끄기, 커스텀 정의 등록.

### 18. 홈 스크롤을 직접 구현, 색 조합 바꾸기
- 문제: CSS `scroll-snap`(mandatory)은 브라우저 기본 스크롤과 싸워서 효과가 약하고 끊겨 보였다.
- 해결(`src/lib/sectionScroll.js`): 휠과 방향키 한 번에 첫 화면, 글 하나씩, 맨 아래로 0.9초 이징 애니메이션으로 이동한다. 트랙패드 관성이 한 칸 더 넘기지 않도록 움직임이 멈췄거나 새로 힘이 붙었을 때만 입력을 받는다. 터치 기기와 모션 줄이기 설정에서는 기본 스크롤을 쓴다. 글이 화면에 들어오면 이미지가 확대에서 제자리로, 설명이 아래에서 올라오며 나타난다.
- 색 조합(`src/lib/theme.js`, `ThemeSwitch.jsx`): 왼쪽 아래 해 아이콘을 누르면 점이 세로로 펼쳐진다. 조합은 배경과 글자색 두 색만 정하고, 회색 단계는 `color-mix`로 자동 계산한다. 선택은 localStorage에 저장되고 화면이 그려지기 전에 적용된다. 목록의 조합 5개는 임시이며 정해진 조합으로 `PALETTES`만 바꾸면 된다.
- 확인: 로컬 빌드에서 검정 조합 적용(배경과 글자색 값), 저장, 가상 휠로 위아래 한 칸씩 이동. 실제 마우스 휠과 트랙패드 감각은 직접 확인이 필요하다.

### 19. 스크롤 단위 정렬, 색 조합 위치, 헤더 간격
- 스크롤: 이동 시간을 0.9초에서 0.6초로 줄이고 easeOutQuart로 바꿔 바로 출발해서 부드럽게 멈추게 했다. 글 카드 높이를 `100svh - 96px`, 아래 간격 96px로 맞춰 글 하나가 정확히 한 화면이 되게 했다(위아래 여백 48px로 같음). "최근 글" 줄은 상단에 고정해 첫 글도 같은 위치에 선다. 모바일 폭(820px 이하)은 높이 고정 없이 기존 배치.
- 색 조합: 왼쪽 아래 해 아이콘을 없애고 상단 '홍지영 기획 노트' 오른쪽에 현재 색 원 하나를 두었다. 누르면 조합 원들이 세로로 70ms 간격으로 튀어나온다(바깥을 누르면 닫힘).
- 전체 글과 글 상세에서 헤더 위 간격이 좁던 문제: 14px 위 여백이 홈 첫 화면 영역에만 있었다. `.hm-top` 자체로 옮겨 세 화면이 같아졌다.
- 확인: 1280x800에서 글 카드 시작 위치 간격이 800px(화면 높이)와 같고 카드 높이 704px, 색 원 5개가 세로로 나타남. 실제 휠 감각은 직접 확인 필요.
